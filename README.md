# 桌面宠物（stm-pet）

ST-Manager 官方插件：一只常驻在界面上的桌面宠物。它会随宿主状态活动、能被拖着走、
松手会下坠、闲时自己溜达、长时间没人理就睡着；卡片更新与扫描完成时它会做出反应；
用户能**自己新建形象**、导入形象包，**按形象**调整大小、渲染方式与触发节奏，
不想看到它时还能**一键关闭**（不必卸载插件）。

- 插件 id：`stm-pet`
- `api_version`：2
- 权限：**不声明任何权限**（不读卡片、不读世界书、不联网）

---

## 1. 安装

把本仓库目录放到宿主的插件目录下，目录名必须是 `stm-pet`：

```
<ST-Manager>/data/plugins/stm-pet/
├─ manifest.json
├─ backend/
├─ frontend/
├─ resources/pets/xiaoman/       随包内置形象：小满（半写实插画）
├─ resources/pets/xiaoka/        随包内置形象：小卡（写实真人）
└─ data/                         用户数据（宿主在插件更新时保留）
```

重启 ST-Manager，或在「设置 → 插件」里启用。桌面端会在屏幕上出现**小满**
（见下方「内置形象」）；移动端**不挂载**（见 §7）。

依赖：只用宿主已装好的 Flask 与 Pillow。**没有新增任何第三方依赖**，
也没有打包器（前端是浏览器原生 ESM，由宿主 `import()` 加载）。

### 内置形象

随包带两个**只读**的人形形象（见 §3.4），没有第三方依赖、也不联网：

| id | 名称 | 风格 | 规格 |
|---|---|---|---|
| `xiaoman` | 小满 | 半写实插画 | 12 动作 / 384×576 / `scale 0.45` |
| `xiaoka` | 小卡 | 写实真人（照片级） | 12 动作 / 384×576 / `scale 0.45` |

两个形象的作者都是 **「官方」**。

两个形象都用了本轮新增的动画能力：**非均匀帧时长**（每帧的停留时间不同，
例如走路 `[280, 220, 280, 220]`、落地 `[90, 130, 320]`）、
**idle 的随机触发**（平时静止，6~18 秒随机动一下）、
**idle 的两套动画**（待机 `weight 5` / 张望 `weight 2`，按权重随机播）、
以及**显式的标准图像**（`still` → 待机首帧）。

> 最后一项是**必须**的：它们的 idle 挂了两套动画，而「张望」的首帧是个
> **抬头看**的姿势。不声明 `still` 的话，随机播到张望之后宠物会卡在那个
> 姿势上——这正是本轮修的问题（见 §2.6）。

**首次安装默认用小满**（`store.DEFAULT_PET_ID`）。理由：照片写实是更窄的偏好
——有人喜欢、有人觉得桌面站个真人不适，而插画风是更安全的默认脸；
想要照片级的用户在面板里切一下即可（切换是按形象记住的，见 §5.1）。
用户显式选过形象之后，这个默认值不再插手。

> 默认形象**不是**「列表里第一个」：列表按名称排序，那会让默认体验
> 取决于名字的字典序——改个名字就悄悄换了新用户的默认形象。

## 2. 宠物包格式

一个形象包是一个目录，里面有 `pet.json` 和若干张 spritesheet 图片。

```json
{
  "format": 1,
  "id": "my-pet",
  "name": "我的形象",
  "author": "你的昵称",
  "size": { "w": 64, "h": 64 },
  "anchor": { "x": 0.5, "y": 1.0 },
  "scale": 1.0,
  "pixelated": false,
  "still": { "sheet": "idle.png", "frames": 4, "frame": 0 },
  "schedule": {
    "idle": { "intervalMs": [6000, 18000], "plays": 1 },
    "roam": { "intervalMs": [3000, 9000] }
  },
  "physics": {
    "gravity": 1800, "walkSpeed": 60, "friction": 0.02,
    "terminalVelocity": 2400, "bounce": 0.15
  },
  "animations": {
    "idle": {
      "variants": [
        { "sheet": "idle.png", "frames": 4, "fps": 2.5,
          "frameMs": [400, 300, 300, 600], "weight": 5 },
        { "sheet": "look.png", "frames": 4, "fps": 2.2, "weight": 2 }
      ]
    },
    "walk-left": { "sheet": "walk-left.png", "frames": 4, "fps": 4,
                   "frameMs": [280, 220, 280, 220] },
    "walk-right": { "sheet": "walk-right.png", "frames": 4, "fps": 4,
                    "frameMs": [280, 220, 280, 220] },
    "fall": { "sheet": "fall.png", "frames": 2, "fps": 3.8,
              "frameMs": [300, 220] },
    "drag": { "sheet": "drag.png", "frames": 2, "fps": 3.3 },
    "land": { "sheet": "land.png", "frames": 3, "frameMs": [90, 130, 320],
              "loop": false }
  }
}
```

### 字段说明

| 字段 | 说明 |
|---|---|
| `format` | 格式版本。**向前兼容**：更高的版本号不拒绝，未知字段忽略 |
| `author` | **作者署名**。会写进包里、跟着导出走——别人拿到包就知道是谁做的。见 §2.4 |
| `size` | 单帧的**逻辑尺寸**（CSS px）。贴图实际像素可以是它的 N 倍（2x 帧） |
| `anchor` | 贴图内哪个点对齐世界坐标。`0.5, 1.0` = 底边中点（脚踩地） |
| `scale` | **形象自带的大小倍率**（可选，默认 `1.0`）。见 §2.2 |
| `pixelated` | 是否按**像素风**渲染（可选，默认 `false` = 平滑）。见 §2.3 |
| `still` | **标准图像**：不播动画时显示的那一帧（可选）。见 §2.6 |
| `schedule` | **时间驱动行为的触发节奏**（可选）。见 §2.7 |
| `physics.friction` | **每秒速度保留比例**（越小刹车越快）。默认 `0.02`；详见 §3.3 |
| `animations.<动作>.sheet` | 相对包目录的路径。**水平排布**（帧 0..n-1 从左到右）；竖排加 `"layout": "vertical"`，多行网格用 `cols` / `rows`（见 §3.9） |
| `animations.<动作>.sheets` | **多页**：一个动作拆成多张图（见 §3.10）。与 `sheet` 互斥 |
| `animations.<动作>.layout: "animated"` | **动图容器**：`.gif` / 动图 `.webp` 直接播，浏览器负责（见 §3.11） |
| `animations.<动作>.frames` / `.fps` / `.loop` / `.layout` | 帧数 / 帧率（**接受小数**）/ 是否循环 / 排布（`horizontal` / `vertical` / `grid`） |
| `animations.<动作>.cols` / `.rows` | **网格排布**的行列数（见 §3.9）。写它就自动切到 `grid`，可只写一个 |
| `animations.<动作>.frameMs` | **非均匀帧时长**（每帧一个毫秒数）。见 §3.5 |
| `animations.<动作>.variants` | **多套动画**（按 `weight` 随机播一套）。见 §3.6 |

> **行走只有方向化动作**：`walk-left` / `walk-right`（侧视）。
> **没有正面 `walk`** —— 正面行走图看起来是「原地踏步 + 平移」，
> 与水平移动的语义不符，2026-10 已从词表里删除（见 §3）。

> **节奏字段在顶层 `schedule`，不在动作里。** 早期版本写成
> `animations.idle.intervalMs`；那个位置现在会**明确报错**并告诉你新写法在哪
> （而不是静默忽略——「设了却不生效」是最难查的一类问题）。
> 上移的原因：`roam`（自动漫游）不是动作，挂不到 `animations` 下面。

### 2.1 尺寸不必是正方形

`size.w` 与 `size.h` 是**各自独立**的，形象可以是任意长宽比——
真人立绘常见的 2:3、3:4 都能直接用，不需要裁成正方形。

单帧尺寸的上限是 **1024 × 1024**（宽高各自判定），下限 1。
超过上限的图在**新建形象**时会被等比缩到上限内（而不是被拒绝）。

### 2.2 `scale`：形象自带的大小倍率

`size` 是单帧的**贴图**尺寸，不等于**观感**尺寸。一张 512×512 的真人立绘与一张
64×64 的像素图，按各自的 `size` 原样显示时前者会占掉小半个屏幕。
作者在包里声明 `scale` 就能表达「我这个形象该缩到多少」，而不是让每个用户自己试。

合法区间 **0.25 ~ 4.0**。优先级（`store.effective_scale`）：

```
用户设置（面板滑块） > 包内声明 scale > 宿主表单的全局 scale
```

### 2.3 `pixelated`：渲染方式

**默认 `false`（平滑插值）**，因为像素风与写实插画对放大方式的要求是**互斥**的：

| 形象类型 | 放大时 | 建议值 |
|---|---|---|
| 像素风 / 低分辨率贴图 | 硬边（否则糊成一团） | `true` |
| 写实插画 / 真人立绘 | 平滑（硬边会出现块状锯齿） | `false` |

用户在面板上可以覆盖它，且**按形象**记住。

> **真实踩过的坑**：`plugin.css` 里原本写死 `image-rendering: pixelated`，
> 同时有一条 `[data-pet-pixelated="false"]` 规则——但**前端 JS 从未设置过这个属性**，
> 于是那条规则永不生效、像素风恒开。用户把倍率调到 2× 以上时，写实插画就会出现
> 块状边缘。修法：默认值反过来（`auto`），由 JS 显式写 `data-pet-pixelated`。
> `tests/test_css_contracts.py` 把这个坑钉成了三条测试。

### 2.4 `author`：作者署名

自定义形象应当能标明**是谁做的**——这样别人拿到一个宠物包，就知道该找谁确认，
也让「发布宠物」这件事成立。内置形象的作者写 **「官方」**。

署名会：

- 写进 `pet.json`（因此**导出形象包时一起带走**，换台机器导入也还在）；
- 显示在面板的形象详情与列表里；
- 在**同名**时用来区分——两个人都做了一个「小猫」，靠作者一眼就能分清（见 §2.8）。

作者可以留空（`""` 是合法值，表示不署名），也可以随时改。

### 2.6 `still`：标准图像（不播动画时显示的那一帧）

```json
{ "still": { "sheet": "idle.png", "frames": 4, "frame": 0 } }
```

也可以只写文件名（单帧）：`{ "still": "still.png" }`。

**为什么需要它。** `idle` 默认是「平时静止 + 每隔一段随机播一遍」（§3.7），
而「静止」原本的实现是**保留刚刚播过的那套变体的第 0 帧**。
作者一旦给 `idle` 挂上第二套动画，静止画面就会跟着变——内置形象的
「张望」就是第二套，它的首帧是个**抬头看**的姿势，于是宠物会卡在那个姿势上，
看起来很奇怪（这正是本轮修的问题）。

标准图像的语义是「**不播动画时显示一个固定的标准姿势**」，与「刚刚播过什么」无关：

| 情况 | 用什么 |
|---|---|
| 包内声明了 `still` | 用它 |
| 没声明 | 回落到 `idle` 主变体的第 0 帧 |

回落值在作者只给了一套 `idle` 时本来就是对的，因此 `still` **不是必填**。
但**只要 `idle` 挂了两套以上动画，就应当显式声明它**——否则静止画面会随
随机结果变。面板会在这种形象上提示。

`frame` 让你从多帧 sheet 里挑一帧当标准图像（例如「idle 的第 3 帧就是我想要的门面」），
不必为此单独切一张图。**面板的「新建形象」与形象详情都能设**，两种来源都支持：

- **复用某个动作的某一帧**（不额外落盘，直接指向那个动作的 sheet）；
- **单独上传一张**（按形象的单帧尺寸归一化后存成 `still.<ext>`）。

标准图像走**与动作完全相同**的解析通路，因此「用户覆盖 > 包内 > 内置」的优先级、
路径安全校验与内容版本号缓存**全部自动成立**。它还支持自己的覆盖文件
（`overrides/still.<ext>`），也能在面板里给任意形象换图。

### 2.7 `schedule`：时间驱动行为的触发节奏

```json
{
  "schedule": {
    "idle": { "intervalMs": [6000, 18000], "plays": 1 },
    "roam": { "intervalMs": [3000, 9000] }
  }
}
```

**只有两个行为能设触发时间**，因为只有它们是**由时间驱动**的：

| 行为 | 默认 | 说明 |
|---|---|---|
| `idle` | `[6000, 18000]` | 闲着的时候偶尔动一下。另有 `mode`（`random` / `loop`）与 `plays` |
| `roam` | `[3000, 9000]` | 闲着的时候自己在屏幕底部走一走 |

其余动作都是**事件驱动**的（`click` 要有人点、`fall` 要松手、`happy` 要有播报…），
给它们设「多久触发一次」没有意义，因此**写进 `schedule` 会直接报错**，
而不是静默忽略——「我明明设了却没生效」是最难查的一类问题。

间隔写 `intervalMs: [最小, 最大]`（毫秒），也可以分开写成
`minIntervalMs` / `maxIntervalMs`（运行期定义与面板用的就是这一种）。
写反了会自动调正，合法区间是 **200ms ~ 1 小时**。

> **包内声明是「作者建议值」，用户还能覆盖。** 用户在设置面板上拖滑块改的是
> `data/settings.json` 里的 `petSchedules`，优先级是
> **用户设置 > 包内声明 > 默认值**（与倍率、渲染方式同一套规则）。
> 这样**内置形象也能调**——它是只读的，但恰恰是大多数用户唯一会用的形象。

### 2.8 重名

**允许重名。** 两个人各自做一个叫「小猫」的形象是很正常的事，
插件要保证的是**技术上的不冲突**，而不是禁止重名：

| 情况 | 行为 |
|---|---|
| 两个形象**名字**相同、id 不同 | 都列出来，靠 **id + 作者**区分（面板卡片带 `data-pet-id`） |
| 导入的包 **id** 与现有形象冲突 | 自动分配新 id（`name-2`、`name-3`…），**绝不覆盖** |
| 导入时显式带 `replace=1`，且目标是**用户自己的**形象 | 覆盖它（这是用户明确要求的） |
| 导入的包 id 撞上**内置**形象 | 一定改名，内置形象永远不被覆盖 |

形象列表的每一项都带 `author`，因此重名时用户不会分不清哪个是哪个。

### 支持的图片格式

`.png` `.webp` `.gif` `.avif` `.svg`

> **`.jpg` / `.jpeg` 不在宿主的插件资产白名单里。** 导入时会**自动转码成 PNG**，
> 并把 `pet.json` 里的 `sheet` 指向一起改掉——用户把一堆 JPEG 打包上传也能用。
> 但**手写** `pet.json` 时请直接用 PNG/WebP。

### 最省事的写法

`sheet` 可以只写文件名，表示单帧：

```json
{ "animations": { "idle": "idle.png" } }
```

**任何一张单帧图都能跑起来**：缺失的动作沿回退链下溯，最终一定落到 `idle`。

## 2.5 自己新建形象（不需要 zip，也不需要手写 pet.json）

设置面板顶部的「**新建形象**」直接建一个用户形象：给每个动作选一张图即可。

- **「待机」是唯一必须的**动作，其它动作缺失时会自动回退到它；
- **单帧尺寸从「待机」推导**，其余动作自动对齐到同一尺寸——
  否则前端按同一 `width`/`height` 切帧，尺寸不一致的 sheet 会错位；
- 形象**不必是正方形**，按图自身的比例走；
- 一张图里横向排了多帧动画时，把**帧数**填上即可（要求图宽能被帧数整除，
  除不尽会给出可读错误并告诉你每帧该是多少 px）；
- 可选的 `fps`；不填则用包格式默认值；
- **作者署名**（可选，但建议填——见 §2.4）；
- **标准图像**（可选，三种选择：不设 / 复用某个动作的某一帧 / 单独上传一张。见 §2.6）；
- **触发时间**（可选，不填就用默认值。见 §2.7）。

建完之后这些都能在形象详情里继续改。

新建出来的形象是**你自己的**（可改、可导出、可删除），与插件自带的形象待遇不同（见 §3.4）。

## 3. 动作词表与回退链（契约）

| 动作 | 级别 | 触发 | 省略时的回退 |
|---|---|---|---|
| `idle` | **必要** | 无输入 | ——（唯一硬必要动作） |
| `walk-left` / `walk-right` | **必要** | 水平移动（按方向取一侧） | → 对侧**镜像** → `idle`（只位移容器，不播帧） |
| `drag` | **必要** | 指针按住拖拽中 | → `idle` |
| `fall` | **必要** | 自由下落中 | → `idle` |
| `land` | 可选 | 触地瞬间 | → `fall` 尾帧 → `idle` |
| `sleep` | 可选 | 长时间无操作 | → `idle`（降频） |
| `click` | 可选 | 被单击 | → `idle` |
| `happy` / `sad` / `angry` | 可选 | 事件播报时 | → `idle` |
| `look` | 可选 | 指针靠近 | → `idle` + 容器翻转（`scaleX(-1)`） |

**「必要动作」的含义不是「不给就报错」，而是「不给就退化为静态位移」。**
没有行走图时，宠物照常走动，只是不播帧。

**行走只认方向化贴图。** 正面 `walk` 已从词表里删除（2026-10）：

- 正面行走图看起来是「原地踏步 + 平移」——两条腿前后交替、人却横向滑走，
  与「水平移动」的语义不符；内置形象（小满 / 小卡）都只出侧视两套。
- 两侧都没给时回退到 `idle`，而不是回退到正面图。
- **只给一侧也行**：另一侧自动**镜像**复用（后端 `mirror=true`，前端 `scaleX(-1)`）。
  但**左右不对称**的形象（小满的卡片发夹只在左鬓、小卡的木牌只在左髋）
  必须自己画两套——镜像会把不对称的细节翻到另一边，这不是引擎能替作者决定的事。
- 「缺行走」在 `missingRequired` 里报的仍是**代号 `walk`**：它表示
  「行走这项需求没满足」，而不是「缺少一个叫 walk 的动作」。
  提供任一侧侧视图即算满足。

**唯一会报错的**是「连 `idle` 都没有」——因为没有它就没有任何东西可显示。
此时的错误信息会说明**当前包里有哪些动作**，并给出修复建议。

### 3.1 回退是后端算好的

插件后端在 `/runtime` 接口里把每个动作的**结论**都算好（含回退到哪个动作、
为什么、一句话解释），前端只负责播。因此设置面板能直接告诉用户
「缺什么、会怎么回退」，而不是只把动作置灰。

### 3.2 动作覆盖（只对**自建**形象开放）

每个动作都能在设置面板里单独换图。覆盖文件落在
`data/pets/<id>/overrides/<动作>.png`，解析优先级：

```
用户覆盖 > 用户包内 > 随包内置
```

**内置形象不参与这套解析**——见 §3.4。

### 3.3 关于 `friction` 的取值

实施提示词给的示例是 `0.85`。按「每秒保留比例」理解，0.85 意味着一次甩出要滑行
约 12 个屏幕宽度、走停后还要滑 30 秒才归零——那不算「松手有减速」，是失控。
本插件默认取 **`0.02`**：走路停下约 0.4 秒，甩出后 2 秒内滑行约 500px。
语义已冻结为**每秒速度保留比例**；包可以自定义。

### 3.5 动画节奏：非均匀帧时长

`fps` 表达的是「平均多快」，而真实动作的帧时长本来就**不均匀**——
起手慢、中间快、收尾有个停顿。用单一 `fps` 播出来是匀速的机械感。

因此每个动作可以额外声明 `frameMs`（**每帧一个毫秒数**，长度必须等于 `frames`）：

```json
{
  "land": {
    "sheet": "land.png",
    "frames": 3,
    "frameMs": [90, 130, 320],
    "loop": false
  }
}
```

上例读作「落地瞬间很快压下去（90ms）→ 回弹一点（130ms）→ 停住（320ms）」。
`fps` 仍可同时给出（表达平均速度、供 UI 显示），但**有 `frameMs` 时以它为准**。

几条规则：

| 规则 | 说明 |
|---|---|
| 长度必须等于 `frames` | 不符时报错，因为「第 i 帧停多久」没有定义 |
| 可以只给一个数 | `"frameMs": 200` 等价于「每帧都 200ms」（均匀） |
| 单帧范围 17 ~ 10000ms | 下限是 60fps（更短的帧在 rAF 下看不见），上限拦「填错了」 |
| 与 `variants` 配合 | `frameMs` 是**每一套**动画自己的（两套的节奏可以完全不同） |

> **帧率也接受小数**（`"fps": 2.5`）。宠物形象的帧数通常只有 2~6 帧，
> 整数档太粗——「4 太快、2 太慢」这种情况用 `2.5` 才有解。

**动画速度倍率**（宿主设置里的 `anim_speed`，默认 `1`）是对上面这一切的
**整体缩放**：`2` 表示播放时间翻倍（更慢）。它同时作用于帧推进与
「播完回 idle」的时长计算，因此不会出现「动作播到一半就被切走」。

### 3.6 一个动作多套动画（按权重随机）

同一个动作可以挂**多套**动画，每次触发按 `weight` **随机选一套**播。
这是「丰富动画数量」的最低成本做法：同一件事（例如「被点击」）画两三个不同的
反应，观感立刻不像复读机。

```json
{
  "click": {
    "variants": [
      { "sheet": "click-a.png", "frames": 3, "frameMs": [90, 110, 260], "weight": 5 },
      { "sheet": "click-b.png", "frames": 4, "weight": 3 },
      { "sheet": "click-c.png", "frames": 2, "weight": 2 }
    ]
  }
}
```

**`weight` 是相对比例，不是百分比。** 上例的触发概率分别是
`5/10`、`3/10`、`2/10`。这样设计的理由是：

> **新增一套动画时不需要改动原有的数字。**
> 两套各 `5` → 各 50%；再加一套 `5` → 各 1/3，前两个 `5` 一个都不用动。

| 规则 | 说明 |
|---|---|
| `weight` 范围 `0 ~ 1000`，默认 `1` | `0` 表示「保留素材但永不随机选中」 |
| 最多 16 套 | 每套都会算出一个 URL 发给前端，不设上限会让包本身很小、代价却在前端 |
| 全部为 `0` 时退化为等概率 | 作者明显写错了，但让宠物卡死比随便播一套更糟 |
| 每一套可以是字符串简写 | `"variants": ["a.png", "b.png"]` |
| 每套可以有自己的 `frameMs` / `frames` / `fps` / `loop` / `layout` | 完全独立 |
| 写了 `variants` 后**不能**在顶层再写 `sheet` | 那会引出「顶层算不算一套」的含糊语义，直接报错 |

**单套动画仍写成扁平形式**（`"idle": {"sheet": ..., "frames": ...}`）：
那是绝大多数包的形态，不会因为引擎支持多套就变啰嗦。

> **回退时会继承全部变体。** `fall` 没有自己的图而回退到 `idle` 时，
> 它也会跟着 `idle` 随机换姿势——否则同一个回退动作永远长一个样，比有图的更呆板。
> **镜像复用**是例外：那条路径只取主变体，因为「翻转朝向」没法用单个
> `mirror` 标记表达多套动画（播错朝向比少播几套糟得多）。

### 3.7 idle 的随机触发（默认行为）

`idle` 默认**不是**一直循环，而是：

```
平时停在**标准图像**（一个固定的静止姿势，见 §2.6）
  ↓ 每隔一段随机时间（默认 6~18 秒）
播一遍待机小动作（随机抽一套变体）
  ↓ 播完
回到标准图像，重新抽下一次的时间
```

理由是「一直循环的待机动画会让宠物看起来在不停抽搐」——
静止 + 偶发小动作才像活着。这是常驻桌面宠物的成熟做法。

**「静止」画的是标准图像，不是「上一次抽到的那一套」**——这一条是本轮修的核心。
内置形象的 `idle` 挂了两套动画（待机 + 张望），旧实现下随机播到「张望」之后
就会卡在**抬头看**的姿势上。详见 §2.6。

```json
{
  "schedule": {
    "idle": { "intervalMs": [6000, 18000], "plays": 1, "mode": "random" }
  },
  "animations": {
    "idle": { "variants": [ ... ] }
  }
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `random` | `random`（平时静止、偶尔动一下）或 `loop`（一直循环） |
| `intervalMs` | `[6000, 18000]` | 随机间隔区间。写反了会自动调正 |
| `plays` | `1` | 一次触发连续播几轮 |

几条实现上的要点（都是踩过的）：

- **等待期间 rAF 是停着的**（省电），因此倒计时用 `setTimeout` 而不是在
  rAF 里累加——后者在循环停掉之后永远不会前进，idle 动画再也触发不了。
- **不影响 sleep**：睡着后状态不是 `idle`，排期被清掉；醒来时重新抽一次，
  于是「醒来立刻抽时间」而不是「补上睡梦中的那一次」。
- **任何交互都会取消排期**：用户刚点过它、按住它、或把它拖走了，
  都不该马上又自己动一下。
- **自动漫游（`roam`）走的是同一套调度器**：它也是「隔一段随机时间发生一次」，
  只是触发后做的是「走一走」而不是「播一遍动画」。两者的间隔都能在面板上调（§5.4）。

### 3.8 点击与拖拽的分工

**按下不会立刻变成拖拽。** 手势按时间与距离两个维度分开：

| 情况 | 判定 |
|---|---|
| 按住 < 0.5 秒且位移 ≤ 5px | **点击**（播 `click` 动作 + 小弹跳） |
| 按住 ≥ 0.5 秒（即使没动） | **拖拽** |
| 位移 > 5px（无论按了多久） | **拖拽**（用户明确在拖，不必等长按） |

在这之前「按下即拖拽」的后果是：用户想点一下，看到的是宠物被拎起来；
手稍微抖一下，松手就变成一次甩出，宠物飞了；`click` 动作几乎触发不到。

阈值定义在 `frontend/gesture.js`（`DEFAULT_HOLD_MS = 500` / `DEFAULT_SLOP = 5`），
判定逻辑是纯函数，因此能在 Node 里逐条测（见 §10）。

### 3.9 帧排布：单行 / 单列 / **网格**（`cols` × `rows`）

**只有一种几何**：帧总是落在一个 `cols × rows` 的网格里，行优先
（先从左到右，再从上到下）。`horizontal` 与 `vertical` 不是另外两套算法，
而是网格的两个特例：

| 写法 | 等价于 | 说明 |
|---|---|---|
| `"layout": "horizontal"`（默认） | `cols = frames, rows = 1` | 帧 0..n-1 从左到右 |
| `"layout": "vertical"` | `cols = 1, rows = frames` | 帧 0..n-1 从上到下 |
| `"cols": 4, "rows": 4` | — | 4×4 网格，左上 → 右下依次播放 |

```json
{
  "animations": {
    "walk-left": {
      "sheet": "walk.png",
      "cols": 8, "rows": 8,
      "frames": 60,
      "fps": 12
    }
  }
}
```

**为什么要有网格排布**：单行排布下，一页能装的帧数被**帧宽**卡死。
内置形象单帧 384px 宽，而单图上限是 4096px（`imports.MAX_IMAGE_DIMENSION`），
于是最多 10 帧。改成多行之后同样的图能装 10×7 = **70 帧**——
同一张图、同样的解码成本，白拿约 7 倍。

**写 `cols` / `rows` 就自动是网格排布**，不必再写 `"layout": "grid"`。
只写一个方向时，另一个按「装得下」自动补（`"cols": 4` 配 13 帧 → 4 行）。

**`frames` 可以小于 `cols × rows`**——网格装不满是合法的，末尾几格透明：

```json
{ "cols": 4, "rows": 4, "frames": 13 }   // 4×4 里只放 13 帧，3 格空着
```

反过来 `frames > cols × rows` 会**报错**（帧放不下，作者一定算错了），
错误信息里会给出需要的行数。不静默丢帧，也不静默扩大网格。

**`layout` 与 `cols` 同时写**时，一致的冗余写法（例如
`"layout": "horizontal"` + `"cols": 4, "rows": 1`）是**允许**的——
`to_dict()` 与工具生成的包都会长这样，一律判冲突会让「导出再导入」直接失败。
只有**矛盾**的写法才报错（`"layout": "horizontal"` + `"cols": 4` 配 8 帧）。

**标准图像（`still`）也支持网格**，因为它可以从**任意一条** sheet 里取一帧：

```json
{ "still": { "sheet": "walk.png", "cols": 8, "rows": 8, "frames": 60, "frame": 37 } }
```

没声明 `still` 时，回落路径会**继承 `idle` 那条 sheet 的网格**——
用单行去切一条网格 sheet，取到的不是「第 0 帧」而是「第 0 行第 0 列」，
单行时两者恰好相同，网格排布时则完全不同。

> **给作者的排布建议**：横构图的动作（例如躺姿睡觉）适合竖排，
> 竖构图的动作适合横排或方阵。排布只影响**图的形状**，不影响播放结果——
> 三种写法播出来的帧序完全一致。

### 3.10 多页 sheet（`sheets`）：支持上百帧

单图的**解码像素**上限是一道硬墙：4096×4096 ≈ 16.8 Mpx ≈ **60 MiB 显存**。
网格化（§3.9）只能把这道墙用满（约 7 倍），要再往上只能**加页**：

```json
{
  "animations": {
    "walk-left": {
      "sheets": ["walk-0.png", "walk-1.png"],
      "cols": 8, "rows": 8,
      "frames": 100,
      "fps": 12
    }
  }
}
```

**帧序是页优先、页内行优先**：先把第 0 页从左到右、从上到下走完，
再进第 1 页。这与单页内 `grid` 的顺序完全一致，因此是自然扩展。

**每页形状相同**（都是 `cols × rows`）。上例 8×8 = 64 格/页，
100 帧占 2 页（第 2 页用 36 格，其余透明）。

| 规则 | 说明 |
|---|---|
| `sheet` 与 `sheets` | **互斥**。同时写会报错，而不是挑一个 |
| `sheets` 长度 | 最多 8 页（`MAX_PAGES`）。上限是**显存**护栏，不是磁盘护栏 |
| 装不下 | `帧数 > 页数 × cols × rows` → **报错**并给出需要的页数 |
| **用不上的页** | 声明的页数超过实际需要的页数 → **报错**（多出来的页永远不会被播到） |
| 网格声明 | 写了 `cols` × `rows` 就是「每页这么多格」；没写则按「帧数 ÷ 页数」平均分 |
| `frames` 上限 | 1024（配合多页从 256 提到 1024） |

> **为什么「用不上的页」要报错**：那是「我明明给了 3 页，它只播了 2 页」
> 这类最难查的问题。包能读、宠物能跑，作者只会以为是引擎的 bug。

**真正的瓶颈是显存，不是文件大小**：一张 4096² 的 sheet 解出来是 64 MiB
常驻显存，与它的 PNG 是 1 MB 还是 9 MB **无关**。因此面板会把每个动作的
解码占用显示出来（「解码后约占 84 MB 显存」），超过 128 MiB 时给出提醒——
用户看不到显存，只能靠插件告诉他。

**前端怎么播**：切页要换 `background-image`（一次解码），而换格只改
`background-position`（零成本）。因此换页时会**预取下一页**
（`new Image()`，走与 `background-image` 同一条资源缓存），
这样第一次跨页也不会卡顿。

> **单动作覆盖只作用于第 0 页**：覆盖的语义是「这个动作换成我的图」，
> 不是「第 N 页换成我的图」。多页动作想换图请改包。

### 3.11 动图容器（`layout: "animated"`）：第二路线

上面三节（网格 / 多页 / 帧序列）都是**帧序列**路线：作者要先把动画拼成
spritesheet。而很多时候你手上**已经有一个现成的动图**了——从别处下载的、
用工具导出的。让它直接能用就是这条路线：

```json
{
  "animations": {
    "idle": { "sheet": "idle.gif", "layout": "animated" }
  }
}
```

**零制作成本**，代价是放弃控制权。两条路线的取舍：

| | 帧序列（`horizontal` / `vertical` / `grid` / `sheets`） | 动图容器（`animated`） |
|---|---|---|
| 制作成本 | 要拼 sheet | **丢进来就行** |
| 每帧时长（`frameMs`） | ✅ 完全可控 | ❌ 写在文件元数据里 |
| 定位某一帧 | ✅ | ❌ |
| 从某一帧取标准图像 | ✅ | ❌ |
| **分页省显存** | ✅ 最多 8 页，峰值被一页卡住 | ❌ **一个不可分割的解码单元** |
| 色彩 | 无损（PNG/WebP） | GIF 只有 256 色 |

#### 资源消耗：真实情况与直觉相反

**动图通常比 spritesheet 更小**，因为它会做帧间压缩（没变的区域直接跳过），
而 spritesheet 是把每一帧完整并排放。同一段动画（内置形象的 12 个动作）：

| 形式 | 字节数 | 相对 sheet |
|---|---|---|
| spritesheet PNG | 5,617,066 | 1.00x |
| 动图 GIF | 1,250,424 | **0.22x** |
| 动图 WebP (q90) | 1,360,994 | **0.24x** |

所以提醒里**不会**说「文件大」——那是错的。真正的代价是**解码占用不可控**：

- 解码量 = 帧数 × 宽 × 高 × 4，**两种路线一样**（像素总数相同）；
- 但帧序列能**分页**，动图**不能**。实测 480×480 的 120 帧动图 = **105 MiB**，
  而且浏览器必须一次把整个动画解出来，插件没有任何办法把它切开。

因此面板会显示每个动作的**真实帧数**与**解码占用**（帧数从文件元数据读出来，
不在 `pet.json` 里），超过 64 MiB（一张 4096² sheet 的解码量）时给出警告。

> **GIF 还是 WebP？** 如果只追求「能用」，GIF 兼容性最好。
> 但小卡这类**照片写实**素材在 GIF 的 256 色下会有可见的色带
> （实测可见像素 PSNR 40.2 dB）；**动图 WebP** 无损是完美的、q95 是
> 46.2 dB（肉眼无差别）而体积仍然只有 spritesheet 的 0.31x。
> 有得选时优先 WebP。

#### 做不到的事会**报错**，不会静默忽略

动图不切帧，因此这些字段对它没有意义，写了就是**错误**：

```json
{ "sheet": "a.gif", "layout": "animated", "fps": 8 }   // ❌ 报错
{ "sheet": "a.gif", "layout": "animated", "frames": 4 } // ❌ 报错
{ "sheet": "a.gif", "layout": "animated", "frameMs": [100] } // ❌ 报错
```

`loop` 同样不许写：动图的循环次数**写在文件自己的元数据里**
（GIF 的 Netscape 扩展、WebP 的 ANIM 块），插件改不了它。
接受一个做不到的声明比拒绝它更糟——你会以为它生效了。

#### 怎么把动图弄进去

| 途径 | 支持 | 说明 |
|---|---|---|
| 导入 zip | ✅ | 把 GIF/WebP 与 `pet.json` 一起打包；**原样保留**，不重编码 |
| 给动图动作「换图」 | ✅ | 上传动图 → 原样落盘（不会被压成第一帧） |
| 新建形象表单 | ❌ | 那个表单是**帧序列**通路（要把图按帧数切开）。上传动图会**明确报错**并指出该走哪条路 |

> **给帧序列动作上传动图会报错**，而不是静默压成第一帧。
> 静默的后果是最难查的一类：你上传了动图，看到的却是一张不动的图，
> 而界面没有任何提示。错误信息会给出两条出路（改用动图容器 / 改用帧序列）。

#### 一处已知限制

`reducedMotion`（系统「减少动效」）的语义是**关掉循环帧动画**。
帧序列路线能做到（我们的 rAF 真的停），但**动图停不下来**——
没有 CSS 能暂停 GIF。插件对此的处理是：改画**标准图像**（一张静态图）
来兑现承诺；作者没提供静态标准图像时只能保留动图。

### 3.4 内置形象严格只读（契约）

**插件自带的形象不允许用户修改。** 这一条落在**存储层**，不是 UI 层面的隐藏：

| 操作 | 自建形象 | 内置形象 |
|---|---|---|
| 换单个动作的图 | ✅ | ❌ `403 builtin_readonly` |
| 恢复某动作原图 | ✅ | ✅（用于清理遗留覆盖，见下） |
| 删除形象 | ✅ | ❌ |
| **导出**形象包 | ✅ | ❌ `403 builtin_no_export` |
| **改名字 / 作者 / 标准图像**（写进 `pet.json`） | ✅ | ❌ `403 builtin_readonly` |
| **调大小 / 渲染方式** | ✅ | ✅ |
| **调触发时间**（idle 小动作 / 自动漫游） | ✅ | ✅ |
| **在设置页预览动画** | ✅ | ✅ |

后三行是**刻意的**：大小倍率、渲染方式与触发时间改的是「**怎么养**」
（用户自己的偏好，落在 `data/settings.json`），不是「**是什么**」（随包资源）；
动画预览更是纯粹的「看效果」，与「能不能改」无关。内置形象恰恰是大多数用户
唯一会用的形象，锁掉它们就没法适配屏幕、也没法调它的活泼程度了。

> **单动作覆盖只作用于第一套动画。** 覆盖的语义是「这个动作换成我的图」，
> 而不是「这个动作的第 N 套换成我的图」——这样规则简单，也不会出现
> 「上传一张图后另外两套动画静默消失」这种怪事。


实现要点：`resolve_frame_path()` 对内置形象**直接跳过 `overrides/`**。
只藏按钮是不够的——文件还在磁盘上就会被解析器捡走。

#### 遗留覆盖的处理

内置形象还可写的版本可能在 `data/pets/<内置 id>/overrides/` 下留过文件。
这些文件**不再生效**，但插件**不会静默删除用户数据**，而是：

1. 在运行期定义里报出 `staleOverrides`；
2. 面板上显示一条提示 + 「清理这些文件」按钮。

静默忽略的后果是「我明明换过图，怎么没变」——用户无从下手。

## 4. 状态机

```
idle ⇄ walk（随机漫游 / 被指定移动）
idle → drag → fall → land → idle
idle → sleep（长时间无操作）→ idle（任何输入）
任意 → happy/sad/angry（事件播报，播完回 idle）
```

> `walk` 是**状态名**，不是动作名。进入该状态后播哪个动作由移动方向决定
> （向左 `walk-left`、向右 `walk-right`），见 §3。

两条硬要求：

1. **任何状态都能被 `drag` 打断**——用户抓它时立刻响应；
2. **`sleep` 期间收到核心事件会唤醒**——用户不会希望「因为宠物睡了所以没看到播报」。

非法迁移会被**拒绝并记录**（不会静默错位）。抓在手里时收到播报会被推迟，
松手后补播——用户的动作优先。

### 4.1 空中不播地面行为（`fall` 的出口只有 `land`）

`FALL` 的合法出口是 **`land`** 与 `drag`，**没有** `idle`。

这一条看着琐碎，但它挡掉了一整类真实故障：坠落期间 rAF **正好在跑**
（`fall` 属于「必须继续跑」的状态），于是漫游倒计时、打盹计时、idle 的随机触发
都在照常推进。任何一个到点就会去改状态——如果 `fall → idle` 是合法的，
宠物就会在**半空中播起待机动画**，接着还能从 `idle` 走去 `walk` / `sleep`，
看起来就是「空中好几个动画轮流播」。

同样的道理，这三类计时器在**离地且不在拖拽中**时一律不推进
（见 `petview.js:updateStateFromPhysics` 的「空中护栏」）——
它们描述的都是「站在地上闲着」的行为，物理上就不该在空中发生。

### 4.2 落地判定：`touchedDown` vs `justLanded`

两个标记回答**不同的问题**，不能混用：

| 标记 | 回答的问题 | 用途 | 触发条件 |
|---|---|---|---|
| `touchedDown` | 「它现在回到地面了吗」 | **状态迁移**（`fall` → `land`） | 离地 → 触地的状态翻转 |
| `justLanded` | 「砸得够不够重」 | **动画选择** | 冲击 > 60px/s |

只用 `justLanded` 会漏掉真实场景：从很低的地方放下、或贴着地面松手时冲击不足，
状态机**永远停在 `fall`**——既没有落地动作，rAF 也永远停不下来（省电失效），
表现为「宠物贴着地面一直播下落动画」。

一次性标记在**每次 `advance()` 开头**清，而不是每个内部 `step()` 开头清：
一帧内可能补算多步（累加器最多 60 步），在 `step()` 里清的话只有最后一步的
结论能被看到——落地恰在倒数第二步时会被擦掉。

## 5. 配置项

标量开关走**宿主的插件设置表单**（`manifest.config_schema`），在「设置 → 插件」
里改：

| 配置 | 默认 | 说明 |
|---|---|---|
| `quiet_mode` | `false` | **勿扰**：只换动作、不弹提示 |
| `announce_cards` | `true` | 卡片更新时播报（已限流） |
| `announce_jobs` | `true` | 扫描 / 索引完成时播报 |
| `show_toast` | `false` | 播报时弹宿主轻提示 |
| `auto_roam` | `true` | 空闲时自己走动 |
| `scale` | `1` | **全局兜底**倍率（0.25–4）；每个形象还能单独调 |
| `sleep_after` | `120` | 无互动多久打盹（秒） |
| `anim_speed` | `1` | **动画速度（越大越慢）**。`2` = 播放时间翻倍 |

`anim_speed` 是对形象包节奏的**整体缩放**：包用 `fps` / `frameMs` 声明自己的节奏，
用户觉得整体太快或太慢时用它统一调，不必去改包。
它同时作用于帧推进与「播完回 idle」的时长计算，因此不会出现「动作播到一半就被切走」。
想单独看某个动作的效果，用设置面板里的**动画预览**（它有自己的预览速度，
不影响桌面上的宠物）。

### 5.1 大小与渲染方式是**按形象**记的

用户明确要求「宠物大小可以自己调节，以应对不同分辨率与不同形象——
二次元形象和真人形象所需的大小不太相同」。因此这两项**不走宿主表单**
（`config_schema` 只支持标量，表达不了「每个形象一个值」），而是：

- 存在 `data/settings.json` 的 `petScales` / `petPixelated` 里；
- 在形象详情页用**滑块**与**二选一按钮**调；
- 切换形象时自动恢复各自的设置，不必每次重调。

优先级（后端 `store.effective_scale` 算好，前端不重复判断）：

```
用户设置 > 包内声明 scale/pixelated > 宿主表单的全局 scale
```

宿主表单里的 `scale` 因此降级为**全局兜底值**，而不是唯一来源。

### 5.2 插件自己的设置（`data/settings.json`）

宿主表单表达不了的**结构化**状态落在插件自己的设置文件里，一共四项：

| 键 | 含义 |
|---|---|
| `activePetId` | 当前形象 id。**空**表示「还没选过」→ 用内置默认形象（小满，见 §1） |
| `petScales` | 逐形象的大小倍率：`{pet_id: float}` |
| `petPixelated` | 逐形象的渲染方式：`{pet_id: bool}` |
| `petSchedules` | 逐形象的触发节奏：`{pet_id: {行为: {minIntervalMs, maxIntervalMs, plays}}}` |
| `petHidden` | 宠物是否**整个隐藏**（`true` = 不显示）。见 §5.4 |

**标量开关不在这里**——它们只声明在 `manifest.config_schema`（上表），
由宿主表单渲染。两边都存一份会引出「改了宿主表单但插件不生效」这类
双写不同步的 bug，所以设置接口只暴露上面这五个键（有测试钉住）。
删除形象时会一并清掉它的逐形象偏好，避免 id 被复用后新形象继承旧设置。

**「勿扰开关」是插件自己实现的**（宿主侧未做，属产品决策）：

- 开启后**仍然换动作**——用户还是要知道发生了什么；
- 但不弹提示，且全屏遮罩期间完全不打扰。

形象管理（新建、当前形象、导入、导出、动作覆盖、大小与渲染方式、
**标准图像、作者署名、触发时间、动画预览**）
不走宿主表单——宿主的 `config_schema` 只支持标量，渲染不了列表与预览图，
因此自带 UI（「设置 → 插件 → 桌面宠物设置」，或**右键宠物**）。

#### 为什么触发节奏落在用户设置里，而不是只写进 `pet.json`

因为它与倍率、渲染方式**同类**：是「这台机器上怎么养」的偏好
（有人喜欢宠物活泼、有人嫌吵），而不是形象本身的属性。放在这里还带来一个
**必要**的好处：**内置形象也能调**。内置形象是只读的（§3.4），
而它恰恰是大多数用户唯一会用的形象——把节奏写死在只读的 `pet.json` 里，
等于让最需要调的那批用户调不了。

包内声明的 `schedule` 因此降级为**作者建议值**，面板会显示出来供对比。

### 5.3 设置页的动画预览

**可以在面板里直接播具体动作**，不必切过去等它在桌面上真的触发一次——
而 `click` / `land` 这类动作几乎等不到。

- 动作列表里点任意一项即可播放；「重播」再看一遍，「暂停」停下，「第 1 帧」回起点；
- **播放规则与桌面上的宠物完全一致**（帧数 / 帧率 / 非均匀帧时长 / 排布都按
  后端的运行期定义走），因此「预览里看到的」就是「桌面上会看到的」；
- 多套动画的动作可以**逐套切换**（按钮上标着各自的权重），用来核对两套都画对了；
- 预览速度滑杆只影响预览，**不会**动到宿主表单里的全局 `anim_speed`
  （否则用户只是试一下，桌面上的宠物却真的变慢了）；
- **内置形象同样可以预览**：只读限制的是「改图」，不是「看效果」。

#### 预览框为什么是正方形

预览框是**固定 168×168 的正方形**，帧几何由 JS 按**单帧真实宽高比**做
`contain` 缩放并**底边对齐**（`preview.js:applyFrameGeometry`）。

- **正方形**是唯一对横竖构图都不偏袒的外框形状。旧框是 112×168 的 2:3 竖框，
  恰好与站立动作同比例，所以一直没人发现问题；而躺姿睡觉是横构图
  （小卡是 627×353），横图被强行拉进竖框就压扁了。
- **底边对齐**（而不是垂直居中）：宠物站在地面上，「脚底」是所有动作共有的
  参照线。垂直居中会让横躺的睡觉浮在半空、与站立的动作对不齐，
  切换动作时画面上下跳。
- 单帧尺寸的优先级与桌面宠物**同源**（`animation.js:frameSizeOf`）：
  **变体自带 > 动作条目 > 包级**。`/preview` 会逐变体与逐动作下发 `size`；
  尺寸未知时（老后端）退回按框铺满，与从前的行为一致。

#### 为什么背景铺在「内层」上

结构是「外框 `.pet-preview-box` + 内层 `.pet-preview-frame-layer`」，
**背景图挂在只有一帧大小的内层上**。

按比例装入必然留白（横构图左右留、竖构图上下留），而 `background-image`
是按**整条** spritesheet 铺的——铺在外框上时，留白处露出来的正是**相邻的帧**。
实测能看到：睡觉的预览框左边缘飘着一个「z」、右边缘挂着半个人影
（都是隔壁帧的内容），比原来的「压扁」更怪。

单个元素解决不了：`background-clip` 裁不了「背景里的某一块」，
而 `mask` / `clip-path` 会连**边框**一起裁掉（框就残缺了）。
内层只有一帧大小，背景被它自己的盒子裁住，邻帧物理上漏不出来。
内层由播放器创建与回收，调用方不必知道这个结构。

用**同页并排 A/B**量出来的效果（竖排 4 帧纯色图，看第 1 帧）：

| 做法 | 帧窗口内的上一帧颜色 |
|---|---|
| 背景铺在外框上 | **25%**（整块漏进来） |
| 背景铺在一帧大小的内层上 | **0%**（剩下的是外框留白底色，正确） |

#### 帧尺寸为什么要对齐到设备像素

`applyFrameGeometry` 会把单帧显示尺寸对齐到**整数设备像素**
（`snapToDevicePixels`，按真实的 `window.devicePixelRatio`）。

帧的显示尺寸常常是小数（400×300 装进 166px 方框 → 高正好 124.5px）。
这时内层边缘落在**半个设备像素**上，那一行会被画成「本帧颜色 + 外框底色」
各一半的混合——看起来是帧底部一条半透明的细缝。实测：不对齐时内层边缘
有 208 个混合像素（底部整行都受影响），对齐后降到 42 个（只剩外框圆角）。

⚠️ 这条细缝**不是**邻帧泄漏，两件事要分开说：

| 现象 | 成因 | 修法 |
|---|---|---|
| 留白处成片露出邻帧 | 背景整条铺在外框上 | 背景挪进「一帧大小的内层」 |
| 内层边缘一条半透明细缝 | 帧尺寸是小数，边界跨半像素 | 尺寸对齐到整数设备像素 |

判据也要分开——邻帧是纯红/纯蓝/纯黄，混入必然让 **R 与 B 严重失衡**；
而外框底色与圆角抗锯齿是**中性**的（R ≈ B）。按「R 或 B 被抬起」判会把
圆角抗锯齿误判成邻帧混入（实测报出 208 个假阳性）。

内层的 `left` / `top` **故意不**对齐：内层边缘跨半像素只会让它与外框底色
混出一条淡边（外框没有背景图，混不出邻帧），而对齐会让底边偏离「贴底」
这个用户明确要求的语义。

#### 切换动作时保留滚动位置

`render()` 是**全量重建**（`root.textContent = ''`），两个滚动容器
（左栏 `.pet-panel-list`、右栏 `.pet-panel-detail`）都会变成新节点，
`scrollTop` 从 0 开始——而预览项一点就 `render()`，于是右栏每次都被弹回顶部。

因此 `render()` 开头用 `captureScroll()` 记下两个容器的位置、末尾用
`restoreScroll()` 还原。两条硬要求：捕获必须在清空 DOM **之前**，
还原必须在挂上 DOM **之后**（游离节点的 `scrollTop` 无效），
并且要**夹到新的上限**（重建后内容可能变矮）。

### 5.4 设置页的「关闭宠物」开关

面板**顶部**有一个开关：不想看到宠物时点一下就行，**不必卸载或停用插件**。

| 状态 | 面板显示 | 按钮 |
|---|---|---|
| 显示中 | 「宠物显示中 · 运行中」 | 关闭宠物 |
| 已关闭 | 「宠物已关闭 · 已隐藏」 | 显示宠物 |

**关掉的是宠物，不是插件**（这条边界很重要）：

- 宠物从屏幕上消失，视图被**真的销毁**——rAF、定时器、全局监听全部回收，
  不留一点空转（关掉就是真的关掉）；
- 插件**仍然启用**：设置面板照常打开、坞入口照常存在、所有接口照常可用。
  否则用户关掉之后就没有任何入口把它开回来了；
- **不碰**当前形象、形象列表、任何设置——关的是「现在看不看到它」，
  不是「用哪个形象」；
- 开关**持久化**：刷新页面 / 重启宿主后仍然是关的。

其它细节：

- 关着的时候**新建形象不会让宠物冒出来**（那会让人以为开关失效了）；
- 重新显示时**重新取一次形象数据**（关掉期间用户可能换过形象）；
- 切换失败会**回滚**，不留「界面说关了、其实没关」的不一致；
- 诊断句柄也能用：`stmPet.hide()` / `stmPet.show()`。

> 为什么不放进宿主的 `config_schema`：那个表单要用户去「设置 → 插件」
> 翻两层才够得着，而这个开关需要**触手可及**。两个地方都能改又会回到
> 「双写不同步」那个坑（见 §5.2）。宿主表单里那些是「功能偏好」
> （播报、勿扰…），这是「存在与否」，语义不同。

### 5.5 设置页的「触发时间」

面板的「触发时间」区有**两个**行为的滑块（下界 / 上界各一个）：

| 行为 | 默认 | 说明 |
|---|---|---|
| 待机小动作（`idle`） | 6~18 秒 | 闲着的时候偶尔动一下。越小越活泼，越大越安静 |
| 自动漫游（`roam`） | 3~9 秒 | 闲着的时候自己在屏幕底部走一走 |

- 滑块**松手才提交**（`change` 而不是 `input`）——否则一次拖动会打出几十个请求；
- 改完**立刻生效**，不必刷新页面（会重排正在等待的那个定时器）；
- **对内置形象同样开放**（见 §5.2 的说明）；
- 「恢复默认触发时间」清掉覆盖，回落到包内声明 / 默认值；
- 只有这两个行为有滑块。点击、下落、播报这些由**事件**触发，没有「多久一次」
  可言——后端也会拒绝，因此面板不渲染它们的滑块。

> 漫游间隔原本是写死的 `3000 + random * 6000`。改成可配置时**默认值保持不变**，
> 否则用户会莫名其妙地觉得「宠物怎么突然走得频繁了」。

### 5.6 调节条：样式与直接输入

所有调节条（大小倍率 / 触发时间的两个边界 / 预览速度 / 新建表单）共用一套外观与
交互，由 `panel.js:createSliderRow()` 与 `attachNumberBox()` 产出。

**外观**复刻宿主「预设全屏编辑器」里的 `.preset-editor-range`：

- `appearance: none` + 用 `linear-gradient` 按 `--pet-slider-progress`
  画出已选区间，手柄自己画（`::-webkit-slider-thumb` / `::-moz-range-thumb`）。
  `appearance: none` 之后**必须**自己给手柄形状，否则手柄会整个消失，
  只剩一条拖不动的色带；
- 进度变量由 JS 在 `input` 时写入——原生 range 没有「已选比例」这个可样式化的
  部分（与宿主的 `--preset-editor-range-progress` 同一手法）；
- 区间非法时（`max <= min`）写入 `0%` 而不是 `NaN%`：`NaN%` 会让整条渐变失效，
  滑块变成一片透明（看起来像坏了）；
- 保留 `:focus-visible` 焦点环——滑块是纯键盘可操作控件，焦点不可见等于不可用。

**每个调节条右边配一个可直接输入的数字框**：

- 数字框与滑块共享**同一份夹取逻辑**（夹到区间 + 按步长对齐），
  因此从哪边改都得到同一个合法值；`min`/`max`/`step` 也直接沿用滑块的，
  不另写一份；
- 数字框**失焦 / 回车才提交**，输入过程中只做视觉回显。每次按键都夹取的话，
  用户想输 `10000` 时打完 `1` 就被夹成下限，后面几位根本输不进去；
- 失焦时**总是**把显示值规整成真正生效的那个数，避免「显示 999、
  实际 3600000」这种说不清的错位；
- 滑块与数字框的 `input` 里**都不发请求**，仍然松手才提交。

### 5.7 形象卡片的两种状态

左侧列表的卡片有**两种互相独立**的高亮，必须能同时看出来：

| 类名 | 含义 | 何时改变 | 视觉 |
|---|---|---|---|
| `is-selected` | 用户正在**看**这一个（右栏显示的是它） | 点左侧任意一张卡 | `inset` 色条 + 描边 + 底色（最强） |
| `is-active` | 这一个正在**用**（桌面上跑的是它） | 点「设为当前形象」 | 描边 + 极淡底色 + 「当前使用中」文字 |

两者的视觉权重刻意排开：选中是用户此刻的操作焦点，给最强反馈；
使用中是背景事实，降为次要信号。两个强高亮互相打架的话，用户反而分不清
哪个是哪个。

色条用 `inset` 阴影而不是 `border-left`：卡片已有 1px 边框，再加一条 3px
左边框会让内容整体右移，切换选中时卡片会「抖」一下。

### 5.8 小预览框的几何（卡片缩略图 + 动作网格）

面板里有两处「只显示 spritesheet 第 0 帧」的小方框：形象卡片的缩略图（40px）
与动作网格的小图（56px）。两处都由 `panel.js:applyThumbGeometry()` 统一写几何，
并且**必须一起处理**。

- 帧图是**整条** spritesheet（例如 4 帧的 idle 是 1536×576），而方框只有 40/56px。
  用 `background-size: contain` 会把整条压进去 → 每帧只剩十几像素，像一团乱码。
  正确做法是「单帧宽 = 方框宽 × 帧数」+ 左对齐，只露出第 0 帧。
- **每个框用自己的帧数**（来自列表接口的 `pet.thumb` / 动作条目），
  不能借用「当前选中形象」的详情——那会让除第一个之外的框全停在 CSS 默认值。
- 两处都通过同一套 `data-` 契约（`data-frames` / `data-layout` / `data-has-image`）
  交给几何函数，因此**加新预览框时不要另写一套**——这个坑踩过三次，
  每次都是「加了一个框，忘了加进选择器」，症状都是「框里什么都没有」。

> 这类问题**只有人眼或截图能发现**：接口正常、数据正常、控制台无报错，
> 只是画面上没有图。所以 `tools/verify-panel.mjs` 会量真实的 `background-size`
> 并断言「单帧显示宽度 = 方框宽度」，而不是只查类名或属性在不在。

## 6. 播报与限流

订阅的核心事件（都走 `api.on()`，SSE 通路）：

| 事件 | 反应 |
|---|---|
| `card.created` / `card.updated` / `card.moved` / `tag.applied` / `worldbook.saved` | `happy` |
| `card.deleted` | `sad` |
| `scan.completed` / `index.job_done` | `happy`（+ 可选提示） |

**`card.updated` 在批量操作时会高频触发**（选 500 张卡改标签 = 推 500 次）。
因此播报采用**前导 + 尾随限流**：

- 窗口 `3` 秒（卡片）/ `1` 秒（扫描与索引）；
- 窗口内的第一次**立刻播**（用户马上看到「它注意到了」）；
- 中间的被丢弃，但**最后一次会在窗口结束时补播**——
  这样批量操作结束时宠物会再动一下，而不是「开头动一下就彻底没反应」。

`scan.completed` / `index.job_done` 尤其值得一提：它们**没有任何 UI 动作触发**，
在这条通路修好之前前端无从得知操作已完成。

## 7. 移动端行为

**移动端不挂载宠物。** 这是宿主的产品决策（屏幕小、常驻图层会遮挡内容且没有
「挪开」的手段），插件不绕过它。

移动端的降级形态：**只剩入口，没有常驻宠物**。用户仍可通过「设置 → 插件」
或顶栏的坞按钮（移动端坞退化为顶栏按钮）打开形象管理面板查看、导入、预览形象
—— 只是屏幕上不会出现常驻的宠物。

坞入口本身不需要插件做任何降级：宿主在移动端会把坞整体换成顶栏按钮
（`entryRegistry.js:180-182` 的注释明确写了这条设计），插件照常声明即可。

判定方式（实测过的一个坑）：宿主的 `surfaces.register()` 在**桌面与移动端都返回
key**，因此不能靠返回值判可用；插件用 `api.surfaces.isOpen('pet')` 判定——
移动端 `_mountAmbient` 提前返回、不写 open 表，所以返回 `false`。
完整论证见 CHANGELOG「与实施提示词的偏差」第 1 条。

## 8. 性能与省电

循环会**自己停**。省电策略（§4.5 的表格逐条落地）：

| 条件 | 行为 |
|---|---|
| 页面不可见 | **停绘** |
| 系统「减少动效」（`reducedMotion`） | **停绘**（不是降速）——只显示一帧静息图 |
| 宿主忙（批处理 / 索引 / 扫描） | 降到 1/4 帧率 |
| 全屏遮罩 / 对话框打开 | 降到 1/4 帧率 |
| 视口 < 900px 宽 | 降到 1/2 帧率 |

其它措施：

- **一个 rAF 循环**驱动一切（物理 + 帧推进 + 状态机），不是每个动作一个定时器；
- **固定步长物理**（1/120s）+ 累加器，表现与帧率无关；
- **帧推进用时间累加**，不用 `setInterval`（掉帧不累积漂移）；
- 帧推进走 **spritesheet + `background-position`**，换帧只改绘制，
  不走网络与解码；
- `will-change: transform` **只在运动期间**加，停下就摘；
- 单帧形象 + 物理静止时，rAF **真的停掉**，有事件再唤醒。

`reducedMotion` 的语义是**关掉循环帧动画**，不是「降速」——用户开这个选项
是因为动效让他不适，降速对他没有任何帮助。CSS 侧同时有
`@media (prefers-reduced-motion: reduce)` 兜底。

## 9. 隐私与权限

- **不声明任何权限**：不读卡片、不读世界书、不读标签、不联网、不跑作业。
- 只订阅核心事件（宿主广播的**事实**，不含卡片内容）。
- 用户上传的图只落在插件自己的 `data/` 目录里，不经网络外发。
- 无遥测、无外部请求。

### 导入安全

用户上传是不可信输入，因此做了：

1. **路径穿越**：`realpath` 后校验在数据目录内；zip 内绝对路径与 `..` 一律拒绝；
2. **解码炸弹**：`Image.MAX_IMAGE_PIXELS` + 显式 4096×4096 上限；
3. **只信内容不信扩展名**：按 magic bytes 判真实格式，PDF/EXE 冒充 PNG 会被拒；
4. **体积上限**：单图 8 MiB、单包 32 MiB、解压后 128 MiB、条目数 2048；
5. **格式白名单 + 转码**：JPEG 等统一转成 PNG/WebP 落盘；
6. **结构化错误**：所有失败都返回 `{success:false, msg, error, hint}`，
   **绝不暴露堆栈**。

### 插件图标

图标由 `frontend/assets/icon.svg` 提供，用在四处：**右侧坞入口**（`entries[].icon`，
`kind: "dock"`）、设置入口（`kind: "settings"`）、设置面板标题、插件总览，
以及宿主轻提示（toast）。

**宿主的渲染方式决定了它必须是「单色剪影」**（`static/css/modules/icons.css`）：

```css
.ui-icon.ui-icon--asset {
  background-color: currentColor;
  -webkit-mask: var(--ui-icon-mask) center / contain no-repeat;
}
```

两个后果：

1. **mask 只看 alpha**，颜色统一由 `currentColor` 决定 —— 多色/渐变会被抹平，
   因此设计成单色填充剪影（深色/浅色主题自动适配）。
2. **`contain` 按 SVG 自身比例缩放** —— 所以 viewBox **必须紧贴内容**。
   原设计稿画布是 1792×2400、内容只占中间一块，不裁剪的话
   在 16px 图标位里只剩一小团。

裁剪由 `tools/crop_icon.py` 完成（可重跑，`--measure` 会核对 bbox 常量）：

```bash
python tools/crop_icon.py --measure   # 核对源文件的 bbox
python tools/crop_icon.py             # 重新生成 + 输出各尺寸对照图
```

`tests/test_icon_contracts.py` 把这些都锁成了测试：viewBox 必须贴内容、
必须是单色、`fill` 必须显式给（mask 下 `stroke` 无效）、
图标路径必须是合法的插件资源路径。

### 坞入口与图标大小

`entries[]` 里声明了**两个**入口：

| id | kind | 作用 |
|---|---|---|
| `pet-dock` | `dock` | 右侧坞里的图标，点击打开设置面板 |
| `pet-settings` | `settings` | 「设置 → 插件」里的条目 |

几条容易静默失效的规则（都已加测试）：

- **坞槽位有限**：全局 8 个、单插件最多 2 个（`core/plugins/entries.py`）。
- **社区插件默认不进坞**：`entryRegistry.js` 的 `isPinned()` 默认值是
  `tier !== "community"` —— 未在 catalog 登记时 `tier` 回落为 `community`，
  入口会进**溢出菜单**而不是坞。本插件在 catalog 里是 `official`。
- **`surface.id` 必须真的注册过**，否则点了没反应（宿主会退化成派发事件，
  插件不监听就静默无响应）。测试用源码交叉验证这一点。
- 坞槽位**只显示图标**，名称靠 `title`/`aria-label` —— 所以 `label` 是必需的。

**图标大小是量出来的，不是算出来的。** 坞槽位是 26px 正方形
（`--dock-icon-size: 1.625rem`，窄屏 24px），图标以 `contain` 缩放，
所以**视觉大小取决于「内容在 viewBox 里的占比」**，光看 viewBox 会估错：

```bash
python tools/measure_dock_icons.py
```

它按宿主真实方式（mask + 实色）渲染两个图标，逐像素量墨迹包围盒并折算回坞尺寸，
最后输出并排对照图。实测结果（与参照的 AI 助手比）：

| | 墨迹宽 | 墨迹高 | 墨迹面积 |
|---|---|---|---|
| AI 助手（参照） | 23.25px | 21.19px | 151 |
| 桌面宠物 | 25.00px | 20.50px | 165 |

高度差 3.3%、面积大 9.5%，在容差内（AI 助手图标自带约 11% 内边距，
本插件的是裁到 2% 的），并排观感协调。

图标也用在**宿主轻提示（toast）**里 —— 通知因此是品牌化的。
这依赖宿主 `ST-Manager@715d0a8` 的修复（该修复由本插件审计发现并提交提示词，
论证见 CHANGELOG「已上报并修复的宿主问题」）：修复前 toast 的图标位只接受
16 个写死的宿主图标名，插件资源路径会被静默丢弃。在**旧宿主**上，
这个图标会降级为「图标位留空 + 一条 console 警告」，**文案照常显示**。

## 11. 已知限制

- **移动端没有常驻宠物**（宿主的产品决策，见 §7）。
- **`api.host.onState()` 没有「能力探测」字段**：插件判定 ambient 是否真的挂载
  只能靠 `api.surfaces.isOpen()`。
- **只有两个行为能设触发时间**（`idle` 小动作 / `roam` 漫游），见 §2.7。
  其余动作由事件触发，没有「多久一次」可言——写进 `schedule` 会直接报错。
- **触发节奏只能设「多久发生一次」**，不能给单个动作设「随机延迟后再播」
  这类更复杂的编排；也不能让 `click` 这类事件动作按时间自己触发。
- **标准图像只能指定「哪张 sheet 的哪一帧」**，不能对某一帧单独做缩放 / 偏移。
- **一个动作最多 16 套动画**，且每套都会算出一个 URL 发给前端（见 §3.6）。
  多页时每页各一个 URL，因此 URL 总数是「套数 × 页数」。
- 没有多宠物 / 多实例：一个宿主里只养一只。
- 形象包支持三种排布：单行（`horizontal`，默认）、单列（`vertical`）、
  **网格**（`cols` × `rows`，见 §3.9）。三者共用同一套帧几何。
- **一个动作最多 8 页**（`sheets`，见 §3.10），且**每一页都要用得上**
  （声明的页数超过实际需要会报错）。帧数上限 1024。
- **多页动作不能单独换某一页的图**：单动作覆盖只作用于第 0 页（§3.10）。
- **显存没有硬上限，只有提醒**：超过 128 MiB 解码量时面板会提示，
  但不阻止使用——够不够用取决于用户的机器，插件无法知道。
- **动图容器不能分页**（§3.11）：它是不可分割的解码单元，
  因此显存占用无法像帧序列那样被压住。作者该用哪条路线取决于
  「手上有没有现成的动图」与「动画有多长」。
- **动图停不下来**：`reducedMotion` 下插件改画静态标准图像来兑现
  「关掉动效」的承诺；作者没提供静态标准图像时只能保留动图（§3.11）。
- **「新建形象」表单不支持动图**：它是帧序列通路。上传动图会明确报错，
  并指出该用「导入形象包」（§3.11）。
- `anchor` 只影响贴图与世界坐标的对齐，不支持旋转 / 缩放锚点。
- **单帧尺寸上限 1024×1024**：更大的图在新建时会被等比缩小。
  宠物是按逻辑尺寸显示再缩放，所以过大的单帧只是白占内存。
- **内置形象的内容不可改**（§3.4）。想要自己的版本，用「新建形象」做一个，
  或者先导出再改——但导出对内置形象不开放，因此只能照着重建。
  （**动画预览 / 大小 / 渲染方式 / 触发时间**对内置形象是开放的：
  那只影响「怎么养」与「怎么看」，不影响「是什么」。）
- **新建表单不预览多帧切分效果**：填了帧数后是否切得整齐，只能建完看效果。
  切分规则本身是确定的（宽度 ÷ 帧数），除不尽会直接报错。
  （建完之后可以用设置页的**动画预览**逐个动作核对。）
- **新建表单不支持一次上传多套动画**：`variants` 目前只能手写进 `pet.json`
  或通过导入 zip 提供。面板只做「一个动作一张图」。
- **单动作覆盖只作用于第一套动画**（§3.4）——覆盖的语义是「这个动作换成我的图」。
- **标准图像与 `idle` 的关系是「默认回落、声明独立」**：没声明 `still` 时它跟着
  `idle` 的覆盖走（换 idle 的图，静止画面一起换）；声明了 `still` 之后两者独立
  （换 idle 不再影响它，要换就换 `still` 自己的覆盖）。见 §2.6。
- **没有正面行走动作**（§3）。宠物只按移动方向播侧视贴图；两侧都没给时退到
  `idle`（照常移动，只是不播帧）。若将来要兼容只画了正面行走图的第三方包，
  需要先把 `walk` 加回词表——目前刻意不加。
- **默认形象是硬编码的 id**（`store.DEFAULT_PET_ID = 'xiaoman'`）。
  定制包若裁掉了小满，会继续回落到列表里第一个可用形象，不会报错。
- **重名只靠 id 保证技术唯一**：两个同名形象在列表里并列，靠**作者**与
  id 区分（§2.8）。插件不禁止重名，也不做「同名警告」。
- **「关闭宠物」是插件自己的开关**，不是宿主的插件启用状态（§5.4）。
  它只影响宠物本身；要连插件一起停用，仍然走宿主的插件管理页。
  另外：**只有设置面板与诊断句柄能开关它**——宠物被关掉之后它自己
  不在了，因此没有「右键宠物关闭」这条入口（右键菜单挂在宠物身上）。
